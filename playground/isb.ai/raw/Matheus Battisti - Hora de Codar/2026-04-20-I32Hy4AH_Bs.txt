  O conceito é absurdamente simples. O Caveman é um system prompt bem escrito que coloca o Claude no modo vai direto no ponto sem firula. Corta artigos, corta filler como sure happy to e I'd recommend, corta hedging, corta repetição. Mantém 100% da substância técnica. O resultado é que respostas de 850 tokens viram 210 tokens com a mesma informação. A economia média oficial do projeto é 75% nos tokens de output, com range real testado entre 22% e 87% dependendo da tarefa. E mais: o output sai 3 vezes mais rápido porque tem menos texto pra gerar.
   
  A parte mais interessante não é a economia. É a ciência por trás. Em março de 2026 saiu um paper acadêmico chamado Brevity Constraints Reverse Performance Hierarchies in Language Models que testou vários modelos forçando eles a darem respostas curtas. A descoberta foi de cair o queixo: forçar modelos grandes a serem concisos melhorou a accuracy em até 26 pontos percentuais em alguns benchmarks. E mais ainda, a hierarquia de performance se inverteu em certas tarefas: modelos menores ficaram melhores que modelos maiores quando ambos foram forçados a ser breves.
   
  A teoria por trás é simples: quando o modelo escreve muito, ele tem mais oportunidades de errar. Cada palavra extra é uma chance de alucinar, de divergir da resposta correta, de adicionar caveat desnecessário que confunde o raciocínio. Quando você força ele a ser breve, ele é obrigado a ir direto na resposta certa. É uma espécie de compressão força clareza. O Caveman explora isso na prática. Não mudou nada na arquitetura. Não é um modelo novo. É um system prompt que transforma o Claude num especialista direto ao ponto.
   
  A instalação é uma linha: npx skills add JuliusBrussee/caveman. Isso baixa as 4 skills do pacote e instala no formato de Skills do Claude Code. Pra ativar basta digitar /caveman dentro do Claude Code. Tem 3 níveis de intensidade. Lite corta menos e mantém mais legibilidade. Full é o default e é o sweet spot. Ultra é compressão máxima pra quando você só quer confirmação rápida. Tem até um modo wenyan que responde em chinês clássico, a forma mais compacta possível, pra mostrar até onde foi a otimização do projeto.
   
  No vídeo testo o Caveman com 7 cenários reais pra mostrar a economia de verdade. Comparativo lado a lado em explicação conceitual, debug de código, criação de endpoint REST. Testes nos 3 níveis de intensidade com a mesma pergunta pra mostrar a diferença de cada um. Construção de um projeto completo do zero: uma API REST de tarefas com Node.js, Express e better-sqlite3, estrutura modular com rotas, controllers e DB separados, seed inicial e endpoints completos. Tudo no modo Caveman pra ver como é a experiência real de codar com a skill ativada.
   
  O pacote não vem só com o Caveman principal. Tem mais 3 skills integradas. Caveman-commit gera mensagens de commit no formato Conventional Commits sem firula, apenas a essência. Caveman-review faz code review de PR em uma linha por issue com localização, problema e fix. E a mais interessante: Caveman-compress, que comprime o arquivo CLAUDE.md que você carrega em toda sessão do Claude Code. Esse arquivo consome input tokens a cada sessão nova. Se você tem 5000 tokens de CLAUDE.md e abre 50 sessões por mês, são 250 mil tokens só de overhead. O compress reduz isso em média 45% preservando 100% do conteúdo técnico: code blocks, URLs, paths, comandos, headings, tabelas.
