  Se você tem projeto Next.js, React, Node ou qualquer codebase em TypeScript/JavaScript que cresceu rápido, esse vídeo é pra você. Cubro instalação, todos os comandos do CLI, os 3 caminhos de integração com agentes de IA, automação em CI e limitações honestas. No final tem comparativo direto com ESLint mostrando o que o Fallow acha que linters não conseguem.
  
  A instalação é simples: npm install --save-dev fallow. O pacote vem com 4 coisas dentro: CLI principal, LSP server pra IDEs, MCP server pros agentes de IA e Agent Skill que o Claude Code descobre sozinho. Roda npx fallow e em milissegundos aparece o resumo completo: total de problemas, taxa de duplicação e score médio de manutenibilidade.
  
  O comando dead-code é onde a ferramenta brilha. Detecta 4 categorias de código morto que linters tradicionais não pegam: arquivos não usados, exports não usados, dependências não usadas e dependências circulares entre módulos. Cada item vem com path do arquivo e linha exata. Tem também o npx fallow fix --dry-run que mostra exatamente quais arquivos seriam removidos antes de você confirmar.
  
  O comando dupes acha código duplicado em duas modalidades. No modo padrão encontra clones literais. No modo semantic ele acha duplicação conceitual: duas funções que fazem a mesma coisa com nomes diferentes. Mostra clone families com todos os arquivos envolvidos e quantas linhas duplicadas tem no projeto.
  
  O comando health calcula a saúde geral do código. Com flag --score dá um score letrado pro projeto (A, B+, C, D). Com --top 10 lista as 10 funções mais complexas com cyclomatic e cognitive complexity. Com --hotspots --ownership cruza complexidade com git churn, mostrando arquivos vermelhos que são complexos e mudam muito (candidatos óbvios pra refatoração).
  
  A integração com agentes de IA tem 3 caminhos. O primeiro é Agent Skill que vem pronto: instala via npm e o Claude Code descobre sozinho. O segundo é MCP Server: você adiciona um bloco no .claude/settings.json com mcpServers.fallow apontando pro npx fallow mcp. O Claude passa a ter acesso a ferramentas tipo mcp__fallow__audit_changes, que ele chama sozinho depois de implementar uma feature pra verificar se introduziu problemas. Se achou, conserta antes de devolver. O terceiro caminho é o output em JSON com npx fallow --format json, que qualquer agente consegue parsear.
  
  Pra automação tem GitHub Action oficial (fallow-rs/fallow@v2) que comenta em PRs apontando dead code novo. Suporta baselines, então o audit só falha em problemas NOVOS introduzidos no PR. Tem também npx fallow hooks install pra pre-commit que bloqueia commits que introduzem dead code.
  
  Limitações honestas: Fallow faz análise sintática pura sem usar info de tipo. Suporta só TypeScript e JavaScript por enquanto. A camada de runtime intelligence é paga, mas a parte estática (que cobre a maior parte do uso) é grátis e open source.
  
  No final mostro o antes e depois do projeto, com comparativo claro de magnitude. Resumo rápido do que torna o Fallow especial: Rust nativo (sub-segundo), 91 plugins, três caminhos de integração (MCP + Skill + JSON), camada estática gratuita e open source.
