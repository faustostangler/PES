  Cada vez que o Claude Code roda um npm install, git status, npm test ou git diff, o output inteiro vai pro contexto e fica sendo relido a cada turno seguinte. Um git diff de 2 mil tokens em 10 turnos vira 20 mil tokens consumidos só de output repetido. O RTK resolve isso filtrando o ruído antes do output chegar no Claude.
   
  Se você usa Claude Code e vive estourando o context limit no meio da sessão, ou se a conta de tokens explode no fim do mês, esse vídeo é pra você. O RTK foi criado por Patrick Szymkowiak como binário Rust único, zero dependências, MIT, e funciona como hook transparente: você não muda nada no workflow, o Claude nem sabe que tá acontecendo. Funciona com Claude Code, Codex, Gemini CLI, Cursor, Windsurf, Cline, Kilo Code e Antigravity.
   
  No vídeo eu começo explicando o problema dos tokens desperdiçados no Claude Code. Quando o Claude roda um comando, o output bruto fica no contexto, e a cada turno seguinte ele relê tudo. É como carregar uma mochila com pedras que você não precisa. Mostro a conta que assusta: 5.500 tokens por turno em 10 turnos vira 55 mil tokens só de output de comando. Com RTK comprimindo 90%, os mesmos 10 turnos consomem 5.500 tokens. Economia de quase 50 mil tokens numa sessão simples.
   
  Mostro também o impacto real reportado por devs usando RTK em produção. Um dev .NET Blazor reportou 80 comandos com 152 mil input tokens e 113 mil tokens salvos, 74,6% de eficiência. Outro dev com 2.900 comandos teve 89% de redução de ruído. Na prática isso significa sessões 3 vezes mais longas antes de bater o context limit.
   
  Depois explico como o RTK funciona internamente. O hook PreToolUse intercepta o comando que o Claude vai rodar, prefixa com rtk, executa, e aplica 4 etapas de compressão: smart filtering removendo ANSI e barras de progresso, grouping agrupando linhas relacionadas, deduplication removendo padrões repetidos, e truncation mantendo erros mas cortando sucesso verboso.
   
  Mostro exemplos de compressão reais: cargo test passa de 155 linhas pra 3, npm install de 4 mil linhas vira 15, npm test de 500 linhas vira 12. Erros e warnings ficam intactos, o RTK só corta sucesso verboso.
   
  Mostro a instalação completa. No Windows você baixa o binário da página de releases do GitHub e coloca rtk.exe no PATH. No Mac e Linux instala via Homebrew com brew install rtk-ai/tap/rtk ou via Cargo. Depois ativa no Claude Code com rtk init -g pra todos os projetos, ou com flags específicas pra outros agentes como Gemini CLI, Codex, Cursor, Windsurf, Cline e Kilo Code.
   
  Aí entra a parte mais importante: demo ao vivo de antes e depois. Primeiro rodo git status, npm install, npm test e git diff sem RTK e mostro o output bruto verboso enchendo o contexto. Depois ativo o RTK e rodo os mesmos comandos, mostrando como cada um vira output limpo mantendo só o essencial. No final rodo rtk gain pra ver os stats de tokens salvos e rtk gain --graph pra ver o gráfico ASCII de economia.
