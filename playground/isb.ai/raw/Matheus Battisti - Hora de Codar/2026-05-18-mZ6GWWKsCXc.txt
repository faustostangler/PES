Diferente do Claude Code e Cursor que têm dezenas de features automáticas, o Pi é minimalista por design e obedece sem improvisar.
  
  Se você usa Claude Code, Cursor ou qualquer coding agent e cansou de ver a IA tomando decisões que você não pediu (over-engineering, scope creep, refatoração não autorizada), esse vídeo é pra você. Cubro instalação rápida, configuração do AGENTS.md (o arquivo que define convenções e estilo do projeto), uso do branching pra comparar modelos diferentes na mesma sessão, criação de extensions customizadas com slash commands próprios, e deploy real em produção com a mesma API key usada em desenvolvimento.
  
  Começo explicando o conceito. O Pi é um coding agent que roda no terminal com apenas 4 tools (read, write, bash, edit) e suporta qualquer provider de IA via API key (OpenAI, Anthropic, Groq, OpenRouter). A instalação é literalmente um curl: curl -fsSL https://pi.dev/install.sh | sh. Roda pi na pasta, ele pergunta o provider, você cola a API key, escolhe o modelo, e pronto. Sem permission popups, sem features escondidas, sem decisões automáticas que você não autorizou.
  
  A primeira feature chave é o AGENTS.md. É um arquivo markdown na raiz do projeto onde você define stack obrigatória, convenções, estrutura de pastas e regras. O Pi lê automaticamente e segue à risca. Diferente de outros agents que improvisam baseado no que acham bonito, o Pi obedece. Se você diz "componentes em /app/components", ele põe lá. Se você diz "sem any, sem console.log", ele respeita. O AGENTS.md vira o contrato.
  
  A segunda feature é o branching de sessões via /tree. É o diferencial técnico mais único do Pi. Você pode voltar pra qualquer ponto da conversa, criar um branch, trocar o modelo (Ctrl+L) e rodar a mesma tarefa com outro provider sem perder o trabalho original. Comparo no vídeo dois modelos da OpenAI na mesma tarefa, salvando os arquivos lado a lado. Zero retrabalho, dois caminhos explorados em uma sessão só.
  
  A terceira feature é steering em tempo real. Durante uma run, você aperta Enter e injeta instrução nova sem cancelar. Se o Pi tá tomando direção errada, você corrige no meio do caminho ao invés de cancelar e refazer o prompt inteiro.
  
  A quarta feature são as extensions customizadas. Você cria um arquivo TypeScript em .pi/extensions/ que adiciona slash commands próprios ao Pi. Os comandos podem chamar APIs do projeto, formatar output, integrar serviços externos. /reload e o comando aparece. O Pi vira ferramenta de automação do próprio fluxo de trabalho.
  
  Mostro também o uso do mesmo provider em desenvolvimento e produção. A API key que você usa local vai pro deploy sem refatoração. Deployо em produção na Hostinger Web Apps que detecta Next.js automaticamente, adiciona variáveis de ambiente e faz build automático.
  
  No veredito final apresento honestamente onde o Pi brilha e onde o Claude Code é melhor. Pi quando você tem stack opinionada e quer que ele NÃO se meta. Claude Code quando você quer hand-holding com features automáticas. Não é um substituindo o outro, são abordagens complementares pra contextos diferentes.
