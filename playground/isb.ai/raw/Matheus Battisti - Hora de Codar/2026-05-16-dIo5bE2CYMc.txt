  Se você usa Claude Code todo dia e ainda fica colando "continue", "corrija isso" ou "tenta de novo" pra ele terminar uma task, esse vídeo é pra você. O /goal resolve esse paradigma de prompt-resposta-prompt criando um loop autônomo: você define a condição final mensurável, ele roda turno após turno verificando se chegou na meta, e só para quando atinge ou esgota o limite.
  
  Começo com a demo viva. Crio um projeto Node.js com 3 bugs intencionais no calculator.js, rodo npm test pra ver os 3 testes falhando, e disparo um /goal pedindo que todos os testes passem, com critério verificável (exit code 0) e restrição (modificar apenas src/calculator.js). O Claude lê o arquivo, identifica os bugs, edita, roda os testes e marca o goal como completo. Tudo isso sem eu mandar mais nenhum prompt.
  
  Os comandos de controle são intuitivos. Barra goal seguido da condição inicia, barra goal sozinho mostra status (turns, tokens, tempo), barra goal pause pausa sem limpar (você pode conversar normal no meio), barra goal resume retoma, barra goal clear cancela, barra goal complete marca como concluído manualmente. Mostro o pause na prática: pauso no meio de um refactor, pergunto qual estratégia o Claude escolheu, ele me explica em chat normal, e depois retomo de onde parou.
  
  A parte mais importante do vídeo é como escrever uma condição boa. Mostro lado a lado o que NÃO funciona ("melhorar a performance do app") e o que funciona ("a função getUsers em src/db.js executa em menos de 100ms para 10000 registros, critério rodar npm run benchmark e ver avg menor que 100ms, restrição não modificar nenhum arquivo além de src/db.js"). Uma boa condição tem 3 pilares: estado final mensurável (exit code, contagem, output específico), como provar (comando que demonstra), e restrições (o que NÃO pode mudar). Limite de 4000 caracteres.
  
  O próximo nível é o paralelismo. Combino /goal com Agent View pra rodar 3 goals simultâneos no mesmo projeto: terminal 1 converte src/utils de JS pra TS com tipagem completa, terminal 2 adiciona JSDoc em todas as rotas de src/routes/api, terminal 3 atualiza express, lodash e axios pras versões mais recentes. Três agentes rodando, cada um com seu contador, sem supervisão manual.
  
  Pra CI/CD mostro o modo -p, que roda Claude Code sem interação humana. Faço um workflow GitHub Actions que pega o repo, instala dependências, dispara um claude -p com goal de fazer testes passarem, e commita as correções automaticamente. Pipeline de auto-fix funcionando, pronto pra colocar em produção.
  
  Cubro também os cuidados de segurança. A variável CLAUDE_GOAL_MAX_STOP_CONTINUES define o cap de turnos (default 500, recomendo abaixar pra 30 em demos). Use Haiku como evaluator pra economizar tokens. Commite antes de rodar goals longos. Goal ativo bloqueia Stop hook nativo. E se a sessão fechar no meio, claude --continue retoma o goal automaticamente.
  
  O combo final do vídeo é /goal mais permissions allow-all (auto mode). Disparo um goal que pede pra implementar endpoint POST /api/users com validação de email e senha, criar os testes correspondentes, e garantir que tudo passa. Deixo rodar do começo ao fim sem tocar em nada. Trabalho 100% autônomo, zero supervisão.
