Olá, sou Matthias da equipe de Relações com Desenvolvedores do Chrome. Neste vídeo, vou apresentar as ferramentas de emulação disponíveis no servidor MCP do Chrome DevTools. Com elas, seu agente de programação emula o agente do usuário, o tamanho da viewport, os modos claro e escuro, as velocidades da CPU e da rede e a localização do dispositivo. Isso permite que os agentes testem sites, simulando a mesma experiência de um usuário real. Se esta é a primeira vez que você ouve falar do servidor MCP do Chrome DevTools, confira primeiro o guia de configuração em vídeo.

O link está na descrição. Depois, volte a este vídeo para aprender sobre casos de uso de emulação. Agora, vamos analisar três casos de uso práticos de como você pode aproveitar os recursos de emulação em projetos de programação agêntica. TUTORIAL COM DICAS DE FERRAMENTAS DE DESENVOLVIMENTO Primeiro, vamos testar os recursos "Perto de mim". São recursos que se adaptam à localização do usuário.

Por exemplo, um app de delivery que verifica se você está na área de entrega, um site de reservas que exibe sua moeda local por padrão ou um varejista que ajuda você a encontrar a loja física mais próxima. Se você já desenvolveu recursos como esses, provavelmente sabe que é possível emular a localização pelo painel Sensors no Chrome DevTools. A mesma funcionalidade está disponível no servidor MCP do Chrome DevTools. Vamos ver a demo do localizador de lojas que configuramos. Posso simplesmente solicitar ao meu agente usando o servidor MCP do Chrome DevTools: "Vá para chrome.dev/devtools-store-locator.

Pesquise por Berlin e confirme se há uma loja sendo exibida. Confirme que não há nenhuma loja em Washington. Por fim, emule Paris como localização e verifique se há lojas listadas." O agente vai abrir uma janela do Chrome, executar as buscas manuais, atualizar as coordenadas de emulação do navegador para Paris e verificar se as atualizações da IU correspondem, tudo de forma autônoma, enquanto posso fazer outra coisa em paralelo. E, se eu complementar o prompt com "Corrija todos os bugs encontrados", posso instruir o agente a trabalhar em um ciclo fechado de feedback.

Nosso segundo exemplo é o teste de navegação responsiva. Os padrões de IU para dispositivos móveis costumam ser bem diferentes dos do desktop, como substituir uma barra de navegação completa por um menu hambúrguer. Em vez de redimensionar manualmente seu navegador para marcar se ambos os menus contêm os mesmos links, deixe o DevTools cuidar disso. Vou instruir o agente: "Acesse developer.chrome.com.

No mobile, clique no menu hambúrguer, verifique os itens de nível superior e confirme que os mesmos itens estão disponíveis na versão desktop." O agente navega até o site, executa a emulação de dispositivo para ambas as viewports, compara os itens e apresenta uma análise detalhada. Ele verifica que as sessões Docs, Case studies, Blog e New in Chrome são consistentes em ambas as visualizações e até destaca as diferenças de layout no seletor de idioma. Por fim, vamos falar sobre bugs de interação. Muitas vezes, os problemas só aparecem quando você realmente usa a interface.

Vamos instruir o agente a testar o fluxo de pesquisa em vários dispositivos: "Em um dispositivo móvel, tablet e desktop, acesse developer.chrome.com, digite uma consulta de pesquisa, mas não a envie. Aguarde as sugestões de preenchimento automático. Garanta que o botão 'Sign in' permaneça visível o tempo todo.

Resuma suas conclusões." É um exemplo interessante porque reúne vários recursos do servidor MCP do Chrome DevTools: automação de navegação, para abrir o site, além de automação de entrada, emulação e ferramentas de depuração, como captura de tela. Depois de definir o prompt, você pode observar o agente redimensionar a tela e interagir com a barra de pesquisa, tudo de forma autônoma. Após concluir os testes, ele informa que o botão de login permanece visível. Mas, no tablet e no mobile, a barra de pesquisa se expande para ocupar todo o cabeçalho, ocultando o link de "Sign in" enquanto o campo está ativo.

São testes responsivos funcionais em viewports totalmente automatizados, incluindo interações.

Esses três casos de uso dão uma ideia de como usar o servidor MCP do Chrome DevTools com recursos de emulação para criar um ciclo fechado de feedback com agentes. Com o DevTools, o agente não precisa apenas supor como o código funciona, ele pode observar como o código se comporta para os usuários no Chrome ou em dispositivos emulados. Para começar a automatizar com o servidor MCP do Chrome DevTools, confira o README em goo.gle/devtools-MCP.
