Task Manager is lying to you. Not intentionally, it's just hilariously bad at telling you if something dangerous is running on your computer. Most people think if it's not in Task Manager, it's not running, which is adorable but completely wrong. Malware developers know this and they've been dunking on Task Manager for decades with techniques that make their code invisible to casual inspection. Here are three levels of evasion malware uses to hide from you and sometimes even your antivirus, and more importantly, how to actually catch them when Task Manager fails you.

Level one is name spoofing and it's almost embarrassingly simple. Attacker takes their malicious exe, changes its name to something legitimate like svchost.exe or chrome.exe, slaps a convincing icon on it, done. You look in Task Manager, see what looks like a normal system process, move on with your life while their malware mines crypto in the background.

Here's the trick, grab Resource Hacker, it's free, open any legitimate program, extract its icon from the resources folder, save it, then open your malware in Resource Hacker and inject that icon. Boom, your virus.exe now looks identical to the real program. Extra evil move, use Unicode characters that look like normal letters so malware.exe becomes mаlware.exe with a Cyrillic 'a' that's visually identical but technically different,

meaning two files can exist in the same folder with what appears to be the same name. How to catch this? Go to Task Manager, Details tab, find the suspicious process, right-click Open File Location. If it's supposed to be chrome.exe but it opens to some random folder instead of Program Files, congratulations you found malware. Check file sizes, the real chrome.exe is like 2MB,

if yours is 47KB something's wrong. Check digital signatures, right-click the exe, Properties, Digital Signatures tab, legitimate software from Microsoft or Google will be signed, random malware won't be. This method is super basic and any decent antivirus catches it immediately, but you'd be shocked how many people still fall for svchost.exe sitting in their Downloads folder. Level two is process injection and this is where it gets spicy. Instead of running their

own process, attackers inject their malicious DLL into a legitimate process that's already running like explorer.exe or svchost.exe. Now when you look in Task Manager you see a completely legitimate process, open its file location and you get the real system file, everything looks normal. But that process has been hijacked and is running malicious code alongside legitimate code. Here's how it works, the attacker's injector finds a target process,

allocates memory inside that process using VirtualAllocEx, writes their malicious DLL path into that memory using WriteProcessMemory, then creates a remote thread in the victim process that calls LoadLibrary to load their DLL. Now the legitimate process is running malware and you can't see it in Task Manager. How do you catch this? You can't with Task Manager, you need Process Hacker or Process Explorer, they're Task Manager on steroids. Download Process Hacker, it's free and open source, find your suspicious process, right-click Properties, go to Modules tab, now you see every DLL loaded into that process. Legitimate Windows processes

should only load DLLs from System32 or Program Files, if you see a DLL loading from C:\Users\YourName\AppData\Local\Temp\ or some sketchy path, that's injected malware. You can right-click and Unload Module to remove it, though sophisticated malware will just reinject immediately so you'll need to find and kill the injector process first. Pro tip, sort by Path in the Modules tab, anything not in system directories is suspicious. Level three is process hollowing and this is nightmare fuel. Attacker starts a legitimate process like notepad.exe in a suspended state so it's frozen before executing any instructions,

unmaps all of its memory so it's now an empty shell, then maps their malicious code into that memory space replacing everything, fixes all the hardcoded addresses and imports manually since Windows isn't handling the loading anymore, then resumes the process. Now notepad.exe is running but it's actually executing malware. You look in Task Manager, see notepad.exe, open file location, it's the real notepad.exe in System32, open it and it's legitimate notepad,

check loaded modules in Process Hacker and they're all legitimate Windows DLLs. Everything looks perfect but it's completely hollowed out and running attacker code. How do you catch this? You have to go deeper, into the actual memory. In Process Hacker, find the suspicious process, right-click Properties, go to Memory tab. Look for memory

regions with Read/Write/Execute permissions, this is a massive red flag because legitimate programs rarely need memory that's writable and executable simultaneously, that's almost exclusively used by malware or anti-cheat software that doesn't want to be reverse engineered. If you see RWX sections in notepad.exe, that's hollowed. Double-click the suspicious memory region to view its contents, if you see strings like "payload executed" or "connection established" or references to your malware's original filename, you've confirmed it's hollowed. The reason Task Manager fails is it only shows you surface-level information, process names, CPU usage, memory usage, but it doesn't show you what's actually loaded inside processes or what memory permissions look like or what DLLs are injected.

For basic users it's fine, for anyone dealing with malware Process Hacker and Process Explorer give you the visibility you actually need, module lists, memory maps, thread information, handle details, everything you need to see what's really happening.
