React é essencialmente uma maneira de construir interfaces de usuário de forma estruturada e escalável . E existem quatro ideias-chave aqui que você precisa realmente entender. Primeiro, os componentes. Em React, tudo é um componente, que nada mais é do que uma parte reutilizável da sua interface de usuário. Em vez de escrever um único arquivo gigante para todo o seu aplicativo, você o divide em partes menores, os componentes.

Isso é importante porque as aplicações no mundo real não são pequenas. Quer dizer, pense no Instagram. Você tem uma barra de navegação, uma publicação, uma seção de comentários e um botão "Curtir". Se tudo isso estivesse em um único arquivo, seria um caos. Os componentes permitem que você construa seu aplicativo em partes , então, se você quiser criar algo como um aplicativo de lista de tarefas, por exemplo, em React, você pode criar um componente de lista de tarefas para armazenar todas as tarefas, um componente de item para exibir cada tarefa e um componente principal do aplicativo para integrar tudo . Em segundo lugar, a gestão estatal. O

objetivo principal da gestão estatal é simples. Isso permite que sua interface de usuário seja atualizada automaticamente quando seus dados [música] forem alterados. Por exemplo, em um aplicativo de lista de tarefas com várias tarefas diferentes, se você usar estado, essa lista de tarefas acaba sendo rastreada pelo React. Cada vez que você adiciona uma tarefa [música] , você está atualizando os dados e o React renderizará automaticamente a interface do usuário para mostrar a nova tarefa adicionada. Se você não usar gerenciamento de estado, não importa o quanto os dados mudem, a interface do usuário nunca será atualizada, o que deixará o usuário confuso. Em terceiro lugar estão os acessórios e o

fluxo de dados. Os props são a forma como os componentes se comunicam entre si. Eles permitem que você passe dados de um componente para outro. Por exemplo, seu componente de lista pode armazenar uma lista de tarefas e, em seguida, um componente filho desse componente pode precisar exibir uma única tarefa que o usuário selecionou. Portanto, você pode usar props para passar os dados da lista de tarefas de forma que a tarefa selecionada seja exibida no componente filho.

Isso realmente ajuda seu aplicativo a se manter organizado e permite que cada componente opere usando os dados de que realmente precisa. Quarto, comportamento assíncrono. Em segundo lugar, o roteamento. O roteamento é a forma como o seu servidor sabe o que fazer com diferentes solicitações. Por exemplo, se alguém quiser criar uma nova tarefa, isso pode seguir um determinado caminho. Se eles quiserem recuperar uma tarefa,

isso envolve outro caminho. Se eles quiserem excluir uma tarefa, isso segue um caminho diferente. O roteamento oferece à sua aplicação uma maneira clara de organizar diferentes ações. Terceiro, bancos de dados e persistência de dados. Por exemplo, em nosso aplicativo de lista de tarefas, sempre que você cria uma nova tarefa, deseja que ela seja armazenada em um determinado banco de dados para que você possa recuperá-la posteriormente.
