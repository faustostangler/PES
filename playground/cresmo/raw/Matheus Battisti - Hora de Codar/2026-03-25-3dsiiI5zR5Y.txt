  O setup original do Karpathy é pra machine learning. O agente edita um script de treinamento, treina por 5 minutos, verifica se o resultado melhorou e repete a noite inteira. Em 48 horas rodou 700 edições. A maioria descartada. Umas 20 sobreviveram. Todas se acumularam sem se cancelar. O CEO da Shopify pegou o conceito e em uma noite rodou 37 experimentos com melhoria significativa sem ser pesquisador de ML.
   
  O padrão por trás é simples: um arquivo com escopo restrito, uma métrica mensurável que define o que significa melhor, um loop autônomo que modifica, verifica, mantém ou descarta e repete, e git checkpoint a cada passo pra ser sempre reversível. Remove qualquer uma dessas peças e o loop quebra.
   
  Pra fazer autoresearch no Claude Code precisa de 3 ingredientes. Goal é o que quer melhorar. Metric mais Verify é um comando que retorna um número. Guard é a proteção contra quebrar o que já funciona. O segredo tá no eval: se não consegue medir com um comando, não consegue iterar automaticamente. Eval bom é npm test com coverage retornando porcentagem ou benchmark retornando latência. Eval ruim é "parece melhor" ou "ficou mais limpo" — mata o loop.
   
  A instalação são 3 comandos: clone do repositório, copiar skills e copiar commands pra pasta do Claude Code. Precisa dos dois, sem os commands os subcomandos como plan e security não funcionam. Tudo que é instalado são arquivos markdown. Nenhum script, nenhum executável. São instruções que o Claude Code lê e segue.
   
  Na primeira demo uso o autoresearch pra aumentar cobertura de testes de um projeto. Configuro goal, metric, verify, guard e scope. O agente roda iterações onde cada uma lê o estado atual, escolhe uma mudança atômica, faz commit antes de verificar pra rollback ser limpo, roda o verify mais o guard e decide se mantém ou reverte automaticamente. A cada 5 iterações imprime status. No final mostra um summary com baseline, resultado final, quantos keeps e discards e qual foi a melhor iteração. Cada mudança aceita é um commit separado no git.
   
  Na segunda demo criei uma skill universal que funciona em qualquer projeto. Ela analisa a saúde do codebase em 5 categorias: segurança, qualidade, higiene, testes e documentação. Dá um score de 0 a 100. Tudo com grep e find sem dependências. Funciona em qualquer OS. Solto o autoresearch pra melhorar o score automaticamente e mostro o agente removendo secrets hardcoded, limpando console.logs, substituindo eval por chamadas seguras, adicionando testes e melhorando documentação. Cada fix é um commit separado que pode ser revisado, cherry-picked ou revertido.
   
  O conceito é poderoso na simplicidade: restrição mais métrica mecânica mais iteração autônoma gera ganhos compostos. Você para de editar código e passa a editar o markdown que diz ao agente como editar código. Define a estratégia, o agente executa a tática. O Karpathy resumiu: um pesquisador com 20 anos de experiência foi superado pelo próprio agente rodando o próprio framework dele. O agente não tinha melhor gosto, só tinha mais paciência.
