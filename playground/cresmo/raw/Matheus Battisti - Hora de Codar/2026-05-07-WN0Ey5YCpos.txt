  Se você usa Codex e cansou de micro-gerenciar cada passo do agente, esse vídeo é pra você. Cubro o conceito do loop autônomo, as 3 features que tornam o /goal especial (compaction automática, token budget e /goal status), o comando complementar /side pra perguntas paralelas, comparativo direto com Autoresearch do Karpathy e Claude Code /loop, e 5 dicas práticas pra extrair o máximo da funcionalidade.
  
  O /goal funciona assim: você define um OBJETIVO FINAL com critérios verificáveis e o Codex entra num loop autônomo de Plan, Act, Test, Review e Iterate. Plan é onde ele planeja o próximo passo. Act é onde executa e escreve código. Test é onde roda testes e verifica no browser. Review é onde avalia o resultado. Iterate é onde volta pro passo 1 se ainda não terminou. O loop repete até o objetivo ser verificado ou o budget de tokens esgotar. É o mesmo conceito do Autoresearch do Karpathy, agora oficializado pela OpenAI dentro do Codex (chamam internamente de Ralph Loop).
  
  A primeira feature chave é a compaction automática. Quando o contexto enche (próximo dos 258 mil tokens), o Codex limpa tudo, mas o objetivo SOBREVIVE à limpeza. Ele re-analisa o projeto com contexto fresco e continua de onde parou. Sem isso, sessões longas travavam por overflow. É o que torna possível deixar o /goal rodando por horas.
  
  A segunda feature é o token budget. Você define um limite de tokens (tipo 200k pra projetos simples ou 500k pra complexos) e quando atinge, o Codex para limpo em vez de travar. Isso controla custo e impede o loop de rodar infinito gastando demais.
  
  A terceira feature é o /goal status. Você verifica progresso em tempo real sem interromper o trabalho do agente. Mostra tempo decorrido, tokens consumidos e fase atual (planning, acting, testing, reviewing). Útil pra monitorar sessões longas sem atrapalhar o loop.
  
  Tem também o comando /side, que abre um chat paralelo pra perguntas. Você pergunta algo (tipo "o que é CORS?") enquanto o /goal continua codando o projeto. O trabalho principal não para, e a resposta aparece num painel lateral. Útil pra estudar enquanto o agente trabalha.
  
  O segredo pra usar bem é dar critérios MENSURÁVEIS no objetivo. Bom: "todos os testes passam, app renderiza sem erro, sem erros de TypeScript no console". Ruim: "faz um app bonito". Se não dá pra verificar com comando, o loop não sabe quando parar.
  
  No comparativo final coloco /goal lado a lado com Autoresearch do Karpathy e Claude Code /loop. /goal é o mais polido com compaction, budget, /side e browser use embutido. Autoresearch é o mais científico com git checkpoint a cada iteração. Claude /loop é o mais integrado dentro do ecossistema Claude Code. Os três resolvem o mesmo problema: parar de micro-gerenciar o agente.
  
  O setup é simples: precisa do Codex CLI atualizado (versão 0.128.0 ou superior, instala com npm install -g @openai/codex) e conta OpenAI ativa (Plus ou Pro). Sem config extra, sem plugin.
  
  Limitações honestas que mostro no vídeo: /goal não faz git checkpoint automático (precisa commitar antes), pode rodar muito tempo se o critério não for verificável, e o budget é obrigatório pra não estourar custo.
