  Até agora usar Claude Code era ter um estagiário muito bom. Ele fazia tudo, mas uma coisa de cada vez. Se o projeto ficava grande, o contexto degradava e a qualidade caía. Com Agent Teams isso muda completamente. Você define um líder, cria teammates especializados, e cada um trabalha no seu pedaço do projeto ao mesmo tempo. O líder coordena, distribui tarefas por uma task list compartilhada, e os agentes se comunicam direto entre si quando precisam resolver dependências.
  
  Pra testar isso de verdade eu criei o FinanceFlow, um app completo de controle financeiro pessoal. Dashboard com gráficos desenhados em Canvas puro, gerenciador de transações com filtros e busca, e um sistema de metas de economia com barra de progresso e animação de confetti quando você bate 100%. Tudo em HTML, CSS e JavaScript puro, sem framework nenhum, sem backend, dados no localStorage. Abre o HTML e funciona.
  
  Dei um único prompt pro líder com o projeto inteiro detalhado. Ele leu, criou a estrutura base, e montou 3 teammates: Dashboard Dev, Transactions Dev e Goals Dev. Cada um recebeu sua missão e começou a trabalhar no seu painel do tmux. Três agentes codando ao mesmo tempo no mesmo projeto.
  
  O momento mais impressionante do vídeo é quando o Dashboard Dev manda uma mensagem direta pro Transactions Dev perguntando qual formato de evento ele deve escutar pra atualizar os gráficos quando uma transação nova for adicionada. O Transactions Dev responde que vai disparar um custom event no document. Eles definiram um protocolo de comunicação entre si sem eu fazer nada. Quando eu adicionei uma transação e voltei pro dashboard, os gráficos atualizaram sozinhos.
  
  Depois de construir o app, montei um segundo time só pra fazer code review. Três revisores trabalhando em paralelo com perspectivas diferentes: segurança, performance e experiência do usuário. O de segurança encontrou innerHTML sem sanitizar. O de performance pegou re-renders desnecessários nos gráficos. O de UX apontou falta de labels nos inputs e problemas de responsividade. Três lentes ao mesmo tempo que um reviewer sozinho provavelmente deixaria passar.
  
  Mostro também quanto tudo isso custou em tokens e dólares, sem esconder nada. Agent Teams custa mais porque cada teammate é uma instância separada. Mas a conta que importa é outra: se 3x o custo te dá metade do tempo e qualidade superior, faz sentido. E dou uma dica de ouro: coloque Sonnet nos teammates e Opus só no líder. Sonnet executa muito bem, Opus coordena melhor.
  
  Pra contextualizar o que isso significa, a própria Anthropic usou 16 agentes com Agent Teams pra construir um compilador C em Rust do zero. 100 mil linhas de código, 2 mil sessões, 20 mil dólares em tokens. O compilador compila o kernel do Linux em x86, ARM e RISC-V. Se 16 agentes constroem um compilador, imagina o que 3 agentes fazem com o seu projeto.
  
  Agent Teams é experimental ainda. Tem rough edges, às vezes um teammate esquece de marcar task como completa, às vezes o líder quer implementar em vez de delegar. Mas o que funciona já é impressionante o suficiente pra mudar a forma como você desenvolve. Você vira o gerente de projeto e as IAs são o time.
