  Neste vídeo eu mostro o arquivo inspirado nas observações do Andrej Karpathy, co-fundador da OpenAI, que identificou 4 problemas sérios do Claude Code: assumptions silenciosas, over-engineering, mudanças colaterais e falta de verificação. Um dev compilou tudo num único CLAUDE.md que instala em 30 segundos e muda como o Claude Code se comporta.
   
  Se você usa Claude Code e vive brigando com over-engineering (pede uma função simples, recebe arquitetura enterprise com factory pattern e abstrações pra uso único), esse vídeo é pra você. O Karpathy disse uma frase que resume o problema: os modelos assumem coisas erradas por você e saem correndo sem verificar, não pedem esclarecimento, não mostram tradeoffs, e adoram implementar 1000 linhas quando 100 bastava. Karpathy Skills ataca exatamente esses comportamentos.
   
  No vídeo eu começo explicando os 4 problemas que o Karpathy identificou. Assumptions silenciosas, onde o Claude interpreta do jeito dele e sai codando sem perguntar, e você só descobre que assumiu errado quando o código já tá pronto. Over-engineering, onde pede simples e recebe 200 ou 300 linhas quando 50 resolviam. Scope creep, onde o Claude mexe em código adjacente, reformata imports e refatora o que tava funcionando, deixando o diff impossível de revisar. E falta de verificação, onde declara pronto sem testar.
   
  Depois mostro os 4 princípios do Karpathy Skills que resolvem cada um desses problemas. Não assuma: declare premissas explicitamente, pergunte se não tem certeza, mostre tradeoffs ao invés de decidir sozinho. Código mínimo: o mínimo que resolve o problema, nada especulativo, zero abstrações pra uso único. Mudanças cirúrgicas: toca apenas no que precisa, cada linha mudada se conecta direto ao que foi pedido. Goal-Driven Execution: define critérios de sucesso antes de codar e loopa até verificar.
   
  Mostro as 3 formas de instalar o Karpathy Skills. A recomendada é via plugin oficial com /plugin install. A segunda é baixando o CLAUDE.md via curl direto do GitHub. A terceira é copiando como skill local em ~/.claude/skills/. Funciona no Claude Code, Cursor, Codex e OpenCode porque são só arquivos markdown.
   
  Depois vai pra parte mais interessante: antes e depois ao vivo. Faço o mesmo prompt em 2 sessões do Claude Code, uma sem Karpathy Skills e outra com. O prompt pede um sistema de cache simples pra respostas de API. Você vê a diferença na prática: sem Skills o Claude cria CacheManager class com strategy pattern, factory pra múltiplos backends e 300 linhas. Com Skills ele pergunta primeiro, mostra tradeoffs entre memory e redis, implementa Map com TTL em 50 linhas e verifica antes de declarar pronto.
   
  Mostro também como saber se o Karpathy Skills tá funcionando no seu workflow, com sinais concretos como menos mudanças desnecessárias nos diffs, código mais simples na primeira vez, mais perguntas de esclarecimento e verificação antes de declarar pronto. Se o Claude continuar over-engineering mesmo com o Skills ativo, reforça no prompt que quer código mínimo.
