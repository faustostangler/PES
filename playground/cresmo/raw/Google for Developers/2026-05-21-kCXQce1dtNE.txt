fera completamente diferente. Para um robô, entender que uma descoloração e um reflexo no chão podem ser causados ​​por um líquido derramado ou descobrir a trajetória exata necessária para mapear uma fábrica movimentada tem sido historicamente um enorme desafio. OK. Isso é ótimo, mas qualquer um pode dizer que está fazendo coisas incríveis. Então, vamos analisar isso com mais detalhes. Em robótica, geralmente seguimos um fluxo de percepção, planejamento e atuação. Os modelos de linguagem visual do Google são perfeitos para esses dois primeiros estágios, incluindo a versão mais recente do Gemini Robotics Embody Reasoning, ou ER 1.6.

Diferentemente de um modelo LLM genérico, o modelo ER é ajustado com base em dados de robótica, especificamente para raciocínio e compreensão espacial, constituindo essencialmente a unidade lógica do sistema robótico. Para que você tenha uma ideia de como isso funciona na prática, vamos analisar algumas das funcionalidades. Primeiro, temos o apontamento 2D e a localização de objetos. O modelo é excepcional na identificação de pontos em objetos, partes específicas de objetos onde você pode querer segurá- los, e na rotulagem geral, ou seja, ao fornecer ao modelo uma lista de objetos para procurar por seu estado, como "sobre a mesa" ou " fechado", ele identifica esses objetos com base em seus estados únicos. O melhor de tudo é que é fácil começar a usar nosso SDK para Python.

Você pode inicializar o cliente, passar o ID do modelo para a versão mais recente do Gemini Robotics ER, seu prompt solicitando os objetos que você está procurando, sejam itens específicos ou solicitações mais abstratas como a chave de fenda que preciso para o parafuso especial, e quaisquer itens de configuração adicionais do Gemini, como temperatura ou nível de raciocínio, para obter uma resposta que você pode usar em seu projeto de robótica. Muito bem, então vamos dar uma olhada mais atenta nos detalhes . Se você já trabalhou com visão computacional, provavelmente já usou um modelo como o YOLO, que foi treinado em conjuntos de dados fixos como o Coco ou o ImageNet. Essas são fantásticas para o que se propõem, mas são vocabulários fechados, o que significa que só conseguem identificar uma lista predefinida de objetos. Se você precisa que seu robô encontre uma ferramenta específica para cortar uma junta de encaixe em cauda de andorinha ao trabalhar com madeira, mas essa ferramenta não estava no conjunto de dados de treinamento , você está praticamente sem sorte.

Com o Gemini Robotics ER, passamos a utilizar um modelo de linguagem de visão, ou arquitetura VLM. Ao usar o método de geração de conteúdo no SDK, você não está apenas executando um script de classificação. O modelo utiliza fundamentação semântica para localizar qualquer coisa que você descreva em linguagem natural. Como a linguagem e a visão são mapeadas no mesmo espaço, o modelo não precisa de um rótulo específico para cada objeto em seu armazém. Isso se chama detecção de objetos por vocabulário aberto .

Você pode pedir a ferramenta que parece ter sido mais usada ou o componente que está superaquecendo no momento. O modelo analisa os dados visuais para fundamentar esses conceitos abstratos em coordenadas precisas. Para os desenvolvedores, isso representa uma grande vantagem, pois elimina a necessidade de criar, rotular e manter modelos de visão personalizados para cada ambiente específico. O motivo pelo qual chamamos isso de raciocínio incorporado, em vez de apenas um modelo de visão, é porque ele entende a física da cena, e não apenas os pixels. Na robótica tradicional, se você pedisse a um robô para limpar a mesa, ele poderia tentar pegar um prato muito pesado para ele, potencialmente danificando uma engrenagem ou deixando o prato cair, porque não entende de peso ou integridade estrutural. A

Gemini Robotics ER possui o que chamamos de bom senso físico. Ao analisar uma cena, o sistema não está apenas tentando identificar o prato e a comida, mas também raciocinando sobre a relação entre eles. O sistema sabe que, para mover um prato, primeiro precisa transferir a comida para recipientes menores que possam ser levantados, ou solicitar intervenção humana. Também compreende que uma garrafa de vidro é frágil, enquanto uma de plástico não o é. Essa camada de raciocínio permite que o robô lide com cenários imprevistos, como saber que não deve tentar levantar uma mesa que está obviamente parafusada ao chão.

É esse tipo de intuição prática que historicamente tem sido um pesadelo para programar manualmente. Além do senso comum físico, existe o raciocínio semântico. Uma das coisas mais difíceis para um robô com inteligência artificial navegar não é necessariamente um ambiente desorganizado, mas sim uma instrução humana vaga. Se dissermos a um robô: "Ei, guarde isso ." De repente, está tentando descobrir o que é isso e para onde é ir.

O modelo ER 1.6 da Gemini Robotics se destaca ao lidar com essa ambiguidade. Ele utiliza o contexto visual do ambiente para fazer uma suposição fundamentada. Se o sistema detectar alguém segurando uma chave de fenda e houver uma caixa de ferramentas aberta por perto, ele inferirá, usando suas capacidades de raciocínio, que o caminho provavelmente se refere àquela caixa específica . Para os desenvolvedores, isso significa que estamos gastando menos tempo escrevendo instruções if/else frágeis para cada possível caso extremo e mais tempo definindo os objetivos reais de alto nível para seus robôs.

Normalmente, quando usamos esses modelos, pensamos em termos de instantâneos, como enviar uma imagem para gerar conteúdo e obter uma resposta. Mas a robótica é inerentemente um problema temporal. Portanto, precisamos pensar no que aconteceu há 10 segundos para resolver o que precisamos fazer agora. Como o Gemini Robotics ER 1.6 é construído sobre a base do Gemini 3 Flash, ele suporta nativamente entradas de vídeo e de múltiplas imagens .

Isso permite o que chamamos de raciocínio temporal de longo prazo. Em vez de perguntar: "A porta está aberta?", É possível transmitir uma sequência de frames da trajetória do robô através de uma instalação. E como o modelo tokeniza esses quadros cronologicamente, ele consegue raciocinar sobre mudanças de estado. Por exemplo, você pode instruir o modelo com algo como: "Observe os últimos 30 segundos do vídeo. A garra conseguiu

segurar o objeto com sucesso ou escorregou?" O modelo não está apenas olhando para o quadro final. Está analisando o movimento e a diferença entre os quadros. Isso muda completamente a forma como detectamos o sucesso. Antigamente, era necessário escrever códigos heurísticos complexos para verificar se uma tarefa havia sido concluída.

Agora, você pode simplesmente usar o modelo como um supervisor temporal que observa o trabalho do robô e confirma se o estado físico do mundo realmente mudou da maneira que você pretendia. O raciocínio nos leva a 90% do caminho, mas às vezes a informação visual é bastante difícil de processar. Um problema que vemos com bastante frequência no Gemini padrão é que as imagens enviadas para o modelo podem não ser muito boas para determinar o que há dentro dele devido ao tamanho, rotação, desordem ou, na verdade, uma série de outros fatores. Resolvemos isso adicionando suporte para visão Gentic ao modelo Gemini Robotics ER 1.6.

Ao habilitar a ferramenta de execução de código com o SDK, o modelo ER agora pode gerar código para etapas intermediárias, permitindo que os modelos manipulem essas imagens por conta própria para obter uma melhor compreensão do conteúdo. Vejamos um exemplo. Imagine que você tem uma linha de produção que fabrica placas de circuito impresso, e uma das etapas envolve extrair o ID exclusivo de um determinado chip para registrá-lo, como o chip ESMT nesta imagem. Em provas de mestrado em direito (LLMs) tradicionais, esse texto pode ser difícil de ler ou pode se misturar com outros textos no quadro. Ao ativar a ferramenta de execução de código, o Gemini escreve o código para capturar a imagem, localizar o chip que você está procurando e, em seguida, recortar a imagem para incluir apenas a área necessária.

Neste exemplo específico, o chip e o texto ainda estão de cabeça para baixo. Assim, o modelo ER da Gemini Robotics realiza mais uma etapa com o código gerado para rotacionar a imagem intermediária em uma orientação mais legível, aumentando consideravelmente a probabilidade de obter os números corretos do chip. A utilidade desse recurso vai muito além da simples leitura de texto, já que o Gemini Robotics ER foi otimizado para a tarefa comum de ler medidores analógicos e compreender ambientes comuns, como fábricas e usinas, para detectar anomalias. Se você tiver um robô circulando em uma instalação, poderá programá-lo para verificar manômetros, garantir que as portas estejam devidamente fechadas, procurar por derramamentos ou neve no chão, ou executar diversas outras tarefas com as mesmas ferramentas simples. Assim que o robô perceber o que está ao seu redor , podemos passar para a fase de planejamento por meio da orquestração de tarefas.

Imagine isso como dar a um robô uma caixa de ferramentas com diversas funções. Em seu código, você pode fornecer ao modelo uma lista de operações específicas que seu robô pode executar, como abrir a garra, mover-se para uma coordenada, detectar objetos, retornar ao ponto inicial ou qualquer outra coisa. Quando você atribui ao robô uma tarefa de alto nível , como colocar o bloco azul na tigela laranja, o modelo Gemini ER divide essa tarefa em uma série de tarefas menores para planejar toda a operação. O sistema analisa a cena, identifica o bloco azul e a tigela laranja e, em seguida, determina a ordem em que as funções devem ser chamadas para abrir a garra, mover-se em direção ao bloco, fechar a garra, movê-la para a zona de entrega, abrir a garra novamente e, por fim, retornar a uma posição neutra. Além da orquestração de alto nível, o modelo ER da Gemini Robotics consegue lidar com o microplanejamento, como a definição de trajetórias que um robô deve seguir.

Em vez de apenas um ponto de partida e um ponto de chegada, o modelo ER da Gemini Robotics pode gerar uma série de pontos de passagem intermediários, além de destacar maneiras de evitar obstáculos. Assim, a parte final do ciclo de percepção, planejamento e execução, como você provavelmente já deve ter imaginado, é a execução. É aqui que a garra encontra o objeto, por assim dizer. Em robótica, atuação é apenas uma maneira sofisticada de dizer que estamos movendo o hardware, geralmente enviando valores específicos para atuadores, motores e juntas, que fazem o robô se mover. Eu sei que a tendência é dizer: "Vejam só essa incrível funcionalidade de IA que vai mudar tudo." Mas, na

robótica tradicional, se você tem uma máquina em uma fábrica repetindo exatamente o mesmo movimento 10.000 vezes por dia, a teoria de controle padrão funciona perfeitamente bem. Mas existem muitos cenários que as pessoas estão explorando agora que não estão em um ambiente controlado, à medida que se aventuram no mundo real. Isso resulta em ambientes desorganizados, cheios de objetos que o robô nunca viu antes e situações que não estavam presentes nos dados de treinamento originais. Por exemplo, um robô circulando pela rua tentando entregar comida poderia encontrar de tudo, desde um sofá velho e de má qualidade bloqueando toda a calçada até um bando de gansos canadenses teimosos e mal-humorados .

Para ajudar a resolver isso, introduzimos nossos modelos de visão, linguagem e ação, ou VLA, incluindo o modelo de robótica Gemini, carro-chefe da empresa , que está atualmente disponível por meio de nosso programa de testes de confiança. Esses modelos mapeiam pixels da câmera e instruções em linguagem natural diretamente para blocos de valores motores. Você dá um comando como: "Limpe a mesa". e o VLA transmite imagens da câmera para determinar exatamente como os atuadores devem se mover para realizar a tarefa. Isso pode até ser usado em conjunto com o modelo ER da Gemini Robotics para gravar um vídeo de uma tarefa maior e dividi- la em partes individuais para execução, permitindo que o robô resolva uma série de problemas menores para concluir o problema maior .

O que torna isso especial é que construímos esses VLAs sobre a infraestrutura de última geração da Gemini. Graças ao amplo conhecimento geral do mundo proporcionado pelo modelo, o robô consegue entender o contexto e os detalhes dos objetos. Por exemplo, quando demos ao nosso robô uma pequena bola de basquete e uma cesta e pedimos que ele fizesse uma enterrada, o modelo conseguiu pegar a bola e colocá-la na cesta, apesar de não ter sido treinado previamente para isso. Além das simples operações de pegar e colocar, também estamos buscando verdadeira destreza. Queremos que nossas máquinas façam mais do que apenas se movimentar, mas estamos treinando nossos modelos para tarefas complexas, como conectar cabos ou realizar operações de precisão com detalhes minuciosos em uma bancada de trabalho.

Por fim, adotamos uma abordagem generalista para as corporeidades. Quer você esteja trabalhando com um humanoide, um quadrúpede ou uma configuração bípede montada, nosso objetivo é atender às suas necessidades específicas. Esses modelos são projetados para serem independentes do tipo de dispositivo, oferecendo um cérebro poderoso e de uso geral que pode ser adaptado a qualquer hardware com o qual você esteja trabalhando. Ao combinar o raciocínio de alto nível do modelo ER com o controle reativo em tempo real do VLA, estamos fechando o ciclo para agentes físicos verdadeiramente autônomos. E para concluir esta rápida visita guiada às ofertas de robótica do Google DeepMind, vamos falar sobre segurança.
