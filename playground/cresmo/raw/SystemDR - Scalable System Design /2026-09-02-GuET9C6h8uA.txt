Earlier state machines in this course modeled one request [music] moving through stages and finishing. This one never finishes. It cycles continuously for as long as your system is [music] running. It starts in monitoring, the

baseline resting state where the system is always watching. When something looks off, it moves to anomaly detected, where Gemini correlates weak signals across multiple dimensions rather than reacting [music] to any single metric in isolation. From there, it moves to diagnosing. Is this actually malicious or just an ordinary load spike that looks unusual but isn't dangerous? Based on that answer, it moves to recovering, where credentials get rotated and state gets cleaned up as needed. And before

anything is declared fixed, it moves to [music] validating, a security check that has to pass before the system is trusted to come back online. Then it loops back to monitoring, but with an updated baseline, because the whole point is that the system [music] gets smarter from every single cycle it runs. Three capabilities are exercised every time this loop runs. >> [music] >> Detect anomalies before they become disasters, respond by automatically fixing what can genuinely be fixed, and learn by updating the baseline so tomorrow's detection is sharper than today's. >> [music] >> And notice recovery is never just a restart.
