You're probably already familiar with the infamous 404 page and maybe even status code 500. HTTP status codes are just three-digit numbers that we've given a specific meaning to. They tell us about the result of our HTTP request. If everything went well, we'll get a 200 level code, maybe a 200 or a 2011. If the server thinks we, the client, screwed up the request, we'll get a 400 level code in the HTTP response. 400 is

just the generic bad request code. 403 on the other hand means we're forbidden. For example, maybe we tried to upload a YouTube video to a channel that isn't ours. And of course, a 404 means we've requested something that doesn't exist. Now, 500 level codes means the server screwed up. They're a little bit more

rare. 500's the generic internal server error code and means the server's down or recent back-end deployment might have introduced a bug. It's usually a try again later situation unless you are the back-end developer that caused it. So, 200 level codes are success. 400 level codes are client error and 500 level codes are server error. So what about

300 and 100level codes? This feels a bit random. Well, 100level codes areformational. And as a web application developer, honestly, you can mostly ignore them. They're used in lower level parts of the HTTP protocol, things that your networking library will handle. You

wouldn't return a 100level code in the happy path of your REST API, for example, and you shouldn't expect to handle it manually in your front-end code either. 300LE codes are redirects. They're used all the time, but often they feel invisible if you're the client. 301 indicates that a resource has been moved permanently. 307 is used for temporary redirects. As a server,

you'll serve them when changing the URL structure of a resource. And as a client, your HTTP library will just handle the redirects automatically. So you usually don't need to worry about them. Now, as a web developer, I do believe that you should know what each level means, right? 100 levelformational, 200 level success, 300 level redirect, 400 level client error, and 500 level server error. But I would

not recommend sitting down and trying to memorize each code individually. After all, like so many things in programming, they're only a Google search away.
