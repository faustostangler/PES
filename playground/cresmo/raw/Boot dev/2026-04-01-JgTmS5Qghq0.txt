Aqui vai uma pergunta simples sobre DevOps para você. O que é pior do que tentar depurar um problema em produção e não encontrar nenhum registro? E quanto ao excesso de toras? Quer dizer, registros mais detalhados são sempre melhores, certo? Bem, até certo ponto. Bem, provavelmente não ter registros

é pior do que ter registros em excesso. Mas pelo menos se não houver registros, você pode culpar os desenvolvedores e voltar a dormir, certo? Às vezes, os desenvolvedores registram informações em excesso, a ponto de criarem um problema de segurança. Exemplos óbvios incluem a vulnerabilidade de segurança de registrar dados de cartão de crédito ou senhas de usuários. Eu sei que você nunca registraria esses dados de qualquer forma, mas e quanto a alguns exemplos menos óbvios ? E quanto aos endereços IP dos clientes

? E quanto aos nomes de usuário e IDs de usuário? Em alguns contextos, essas informações podem ser consideradas informações de identificação pessoal ou PII (Informações de Identificação Pessoal) e podem estar sujeitas a regras especiais de tratamento. Quando se trata de privacidade e registros, há muitos fatores a serem considerados. Precisamos de alguma forma de tornar isso mais fácil de entender. Aqui estão

cinco maneiras de tornar seus registros de atividades mais seguros. Número um: registro mínimo de dados. Registre apenas as informações que você sabe que precisa para depurar um problema. Número dois, remova informações sensíveis. Remova senhas, chaves de API, números de telefone de clientes ou quaisquer outros dados sensíveis das mensagens de log antes de efetuar o registro. Número três:

utilize um middleware de registro de logs para remover informações potencialmente sensíveis que você possa ter deixado passar. Uma chave de login chamada senha? Basta substituir o valor por "redacted". Número quatro: por mais tentador que seja ao depurar uma API de terceiros, nunca registre a solicitação ou resposta completa da API. Esses documentos geralmente contêm chaves de API ou dados confidenciais de clientes que ainda não foram processados. E, em quinto lugar, se

você realmente precisar de dados sensíveis para fins de depuração, ofusque-os ou criptografe-os. Por exemplo, se estivermos depurando uma chamada de API e precisarmos saber qual chave de API está sendo usada, basta registrar os três últimos caracteres da chave de API em vez da chave completa.
