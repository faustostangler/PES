Not everyone in the world loves TypeScript. DHH, the creator of Ruby on Rails, famously declared that he's done with TypeScript and prefers to work in the dynamically typeyped world of JavaScript, which to be honest sounds about right if you like Ruby, a famously dynamic language. Now, I love TypeScript personally. At least I like it more than JavaScript. And I've been using it over JavaScript almost anytime I have that choice to make. Let's talk about why it

exists in the first place and then what exactly Typescript is because it's not your typical programming language. The big picture why is simple. JavaScript is dynamic and loosely typed. When you write plain old JavaScript code, you get hardly any in-editor tooling to go along with it. Your functions don't have parameter types or return types. And

objects that you pass around don't have a designated structure to them. If you have a function that's supposed to return a number, but you accidentally return a string, there's no tooling that's going to tell you about your mistake. Most likely, you'll deploy those types of bugs to production, and you'll only notice the problem when users start sending you angry support emails telling you your site is broken. The creators of TypeScript were developers at Microsoft. Many of them had C experience. Now, C is a statically

typed language, and these developers were sick of dealing with dynamically typed JavaScript all the time. So, they decided to build a language with types that would compile down to JavaScript because JavaScript is really the only language that runs in the browser, at least if you forget about Web Assembly. So they made Typescript as a superset of JavaScript which means all JavaScript code is actually valid TypeScript code. The difference is that in TypeScript you can optionally add more syntax to provide stricter and stricter type information to the compiler. The more and better the type information you provide, the more powerful your editor's tooling becomes and the more powerful the TypeScript compiler's checks become.

And at its core, TypeScript's compilation isn't about speed. Sometimes it's tempting to think, oh, compiled language means fast. But that's not really what we're talking about here. TypeScript's compiler TSC is all about correctness. It's about the ability to ensure all the types in your codebase are correct and eliminate type bugs before you even run your code. I think

it's fair to think about TypeScript as less of a traditional programming language and more as an advanced llinter for JavaScript.
