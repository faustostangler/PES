Aprenda sobre o loop de eventos do JavaScript, um conceito fundamental que todo desenvolvedor deve dominar. Por meio de animações e diagramas, você aprenderá como o JavaScript gerencia tarefas assíncronas, mantendo-se em uma única thread. Você aprenderá as diferenças cruciais entre a pilha de chamadas, as APIs da web, a fila de retorno de chamada e a fila de microtarefas de alta prioridade. Ao final deste vídeo, você terá uma compreensão visual de como esses componentes trabalham juntos para manter seus aplicativos funcionando sem problemas e sem travamentos. Este curso foi criado para este fim. O

loop de eventos é um dos conceitos mais importantes em JavaScript e, honestamente, um dos mais incompreendidos. Muitos desenvolvedores usam código assíncrono todos os dias. Poderia ser uma promessa, poderia ser um observable no caso do Angular, poderia ser um temporizador, ou poderia ser a realização de chamadas à API e a busca de dados no servidor. Mas quando se trata de como as coisas realmente funcionam por dentro, aí a coisa complica. Mas eis a realidade. Se você compreendeu

profundamente o JavaScript assíncrono e o loop de eventos, então você é capaz de se sair bem em praticamente qualquer entrevista de emprego para desenvolvedor front-end. E o mais importante, você pensará como um desenvolvedor sênior ou experiente que entende exatamente como o JavaScript funciona internamente. Agora, quando analisamos os detalhes, o loop de eventos é apenas uma pequena parte de um sistema maior. No navegador ou ambiente de execução JavaScript, temos um mecanismo JavaScript com uma pilha de chamadas. Temos um ambiente de API web para conexão com o mundo externo. Em seguida,

temos uma fila de tarefas, uma fila de microtarefas e, finalmente, um loop de eventos, que conectará tudo. E todos esses componentes trabalham juntos para tornar o JavaScript não bloqueante, mesmo sendo de thread única. Então, antes de abordarmos cenários complexos, vamos começar pelo básico. Você sabe que o JavaScript é de thread única. Significa que temos apenas uma pilha de chamadas, e essa pilha de chamadas gerencia a ordem de execução do seu programa. Agora, para

entender a pilha de chamadas, vejamos um exemplo muito simples em JavaScript. Temos um `console.log` no início, depois temos a definição de uma função, chamamos a função e, finalmente, temos um `console.log` no final. E sabemos que, antes mesmo de executar uma única linha de código, o JavaScript cria a memória para todas as variáveis ​​e funções, e cria o contexto de execução global. Esse contexto de execução global

é adicionado à pilha de chamadas. E agora, temos a execução da primeira linha. Ao executarmos a primeira linha, teremos um "console.log" impresso no seu console, e então o JavaScript passará para a próxima linha. Não temos nada para executar aqui, e o código irá diretamente para a chamada da função. Quando temos uma

chamada de função, o JavaScript cria um novo contexto de execução para essa função, que é então inserido na pilha de chamadas. E agora, temos aqui a execução da função. Então, temos o console.log, que vem com o comando run, e isso é impresso na tela, e concluímos a execução da nossa função. Assim que a execução desta função for concluída, o contexto de execução da função será removido da pilha de chamadas. O JavaScript passará para a próxima

linha e terminaremos nosso script. Aqui, a mensagem "fim" será impressa no console e, assim que a execução do script for concluída , o contexto de execução global também será removido da pilha de chamadas. É assim que a pilha de chamadas gerencia a ordem de execução do seu programa e garante que apenas uma coisa seja executada por vez na sequência. Cada chamada de função é inserida na pilha de chamadas, executada e removida da pilha de chamadas quando sua execução é concluída. Simples, previsível e perfeito para seu código síncrono.

Mas é aqui que as coisas ficam interessantes. Essa abordagem funciona perfeitamente quando seu código é executado linha por linha, sem esperar por nada. Mas as aplicações na vida real não são tão simples assim, certo? O que acontece quando precisamos esperar por algo? Talvez precisemos usar os temporizadores no seu código, talvez você precise fazer uma chamada à API ou precisemos nos conectar a diferentes recursos, certo? E a

pilha de chamadas não consegue lidar com isso sozinha. Temos apenas uma pilha de chamadas e sua única função é executar tudo o que entra nela . aplicativo mais lento ou até mesmo congelá-lo completamente , certo? E isso não é o ideal. Em aplicações web, frequentemente precisamos nos conectar com recursos externos. E precisamos trabalhar nas promessas, certo? Podemos fazer a chamada à API, buscar os dados e, nesse meio tempo, precisamos esperar pela resposta. Ou talvez você precise trabalhar no

evento. Podemos ter um botão e adicionar o evento a ele. E ao clicar nesse botão, algo será executado. E para lidar com todas essas tarefas, o JavaScript se apoia em um superpoder adicional que está presente fora da pilha de chamadas. E obteremos todos esses superpoderes por meio de APIs da web. Agora, vamos entender o que são as

As APIs da Web fornecem um conjunto de interfaces que permitem conectar-se a recursos externos. atrasar alguma execução. Em seguida, temos uma API web relacionada a requisições HTTP ou de rede, chamada fetch. Estamos usando o fetch para chamar os serviços de backend. Para acessar os elementos do DOM, utilizamos diferentes APIs do DOM. Poderia ser ` document.getElementById`, `
