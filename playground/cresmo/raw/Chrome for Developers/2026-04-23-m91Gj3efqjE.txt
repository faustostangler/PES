Estamos de volta! Hoje, vamos usar a prancheta para criar nossas avaliações. Primeiro, definimos o que é sucesso e fracasso para os nossos dados. Vamos usar nosso app ThemeBuilder como exemplo. Primeiro, podemos ver uma chave com nome incorreto ou uma matriz simples de cores quando esperávamos uma estrutura JSON específica.

Ou podemos receber um slogan que ultrapasse nosso limite rígido de seis palavras. Talvez você pense que usar uma API de modelo com modo JSON ou saídas estruturadas significa que seu trabalho está concluído, mas não está. Ter uma sintaxe válida é ótimo, mas seus dados ainda podem estar incorretos do ponto de vista da lógica de domínio, como códigos HEX, cores inválidas ou valores que simplesmente não fazem sentido. Certo, vamos falar de falhas subjetivas. Imagine pedir uma vibe de "café aconchegante" e receber de volta um slogan corporativo frio.

Ou, pior ainda, você recebe um slogan tóxico. O mesmo acontece com a paleta de cores. Você pode acabar com cores neon conflitantes que arruínam totalmente a vibe aconchegante. Agora que conhecemos nossos modos de falha, vamos mapear nossa estratégia. Usamos avaliações com regras para questões objetivas, como formatação e contraste, e usamos nosso LLM avaliador para aspectos subjetivos, como adequação à marca e toxicidade.

Uma dica: você nem precisa criar cada avaliação do zero, já que muitas ferramentas de avaliação oferecem métricas prontas. E não se esqueça: elaborar suas avaliações não é uma tarefa única. Continuamos a aprimorar nossas avaliações à medida que o app cresce. Confira o artigo desta semana sobre como criar avaliações, experimente e compartilhe seu progresso. Na próxima semana, vamos falar sobre como implementar um conjunto de avaliações e até mesmo um LLM avaliador básico.

Até breve!
