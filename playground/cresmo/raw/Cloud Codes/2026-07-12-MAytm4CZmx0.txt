OpenCV5 just dropped. The first major update to the world's biggest vision library in almost eight years, and the headline is genuinely absurd. OpenCV can now run large language models, natively. The library you reached for to blur a webcam feed or find edges now runs a chatbot. Let that sink in. Quick context. The last big version, OpenCV4, landed back in 2018. In AI years, that is a geological era. And in those years, vision quietly became deep learning, while OpenCV's own AI support fell behind. So the team did the terrifying thing. They ripped out the deep learning engine and rebuilt it from scratch. The old engine understood about 23% of modern AI models. The new one handles over 80%. That is the gap between an unsupported layer crash and your model just loading and running. And here is the kicker. On a plain CPU, it now beats on the next runtime on a whole pile of real models. This is a massive release. Let us walk through everything that changed and everything it breaks. Start with that engine because it is the whole story. In OpenCV4, deep learning was bolted on the side. It worked for simple networks, but the second you loaded a modern model, you hit a wall of missing operations. The rebuild is a proper inference runtime. It is graph-based with real shape inference, constant folding, dynamic shapes, and control flow. The branches and loops that today's models actually rely on. And the migration is clever. There are three engines inside. The new one runs first. If it can't load your model, it silently falls back to the classic engine. You can also route straight to on and x runtime when you want. Now the part one did not see coming. On CPU, the new engine is not just competitive, it wins. Benchmarked against on and x runtime on an Intel i9 x-feet ran 31% faster. Oblevel 2 was 37% faster, and by refnet, a background remover was 32% faster. And these are not cherry-picked wins. Across the whole suite, mobile net, resnet, yolo, vision transformers, all the way up to the giant Sam 2 encoder. OpenCV trades blows with on an x runtime instead of trailing it, and it is not one lucky chip. On an Apple M1, OpenCV's YOLAV 8 finished in 41 milliseconds against on and x runtimes 54. On AMD, a vision transformer ran nearly twice as fast. This engine is legitimately good. Under the hood, it handles quantized models directly and fuses attention using flash attention style tricks. That is the kind of engineering you expect from a dedicated AI framework, not a vision library. One honest catch, and it is a real one. The new engine is CPU only for now. GPU support, CUDA, and tensor RT is on the roadmap for later in the 5. X line. Need the GPU today? You force the classic engine, but raw CPU speed is not why this release is everywhere right now. This is. OpenCV can run language models and vision language models. Start to finish on its own, and on its own is the important part. It ships a built-in tokenizer, so there is no extra Python dependency. It has a kv cache for fast generation, the attention layers, the decode loop, all of it lives inside OpenCV. And these are not toy models. It runs qn 2.5. It runs Google's Gemma 3 and Poly Gemma. It runs GPT family models. Inside the thing you installed to resize images, here is the demo that got me. You feed it a photo of a footballer on a pitch and ask what it sees. OpenCV answers, in plain English, the best football players in the world. No pie torch, no server, just OpenCV. And this is not a rough approximation. The team reports the output matches on and X runtime token for token on the same prompt. It is the real model running, not a watered down port of it, and it is not buried in some internal test either. The VLM demo ships in the repo as a complete runnable script. You clone it, point it at an image, and it talks back for a vision library that is genuinely wild. And since they clearly were not sleeping, they added generative vision too. Lama in painting to erase objects out of a photo plus a diffusion-based in-painting pipeline in OpenCV. I am still adjusting to that sentence. Okay, huge new powers. Now the part that will actually touch your copase, because to make room, they finally took out the trash and some of it was load-bearing. The original CAPI is gone, fully deleted. Every CV create map, every CV find contours, the old CV map struct removed. That interface is over 20 years old, and version 5 finally closes the book on it. C++17 is now the minimum standard. Python 2 support is deleted for good. It is Python 3.6 and newer only. And if you have battled numpy deprecation warnings for years, numpy 2 is finally supported. Entire modules moved out. The graph API and the classic machine learning module were pushed into OpenCV contribute. For traditional ML, the docs now literally point you at scikit-learn instead. OpenVX support was dropped entirely. And that giant bloated Calib 3D module, the one everyone complained about, got split into four focus modules, geometry, calibration, stereo, and point clouds. Your imports will change, but the code finally makes sense. The features module got the biggest glow up. Alongside the classics like Shift and Orbe, it now ships deep learning detectors, Ellicock and Disk, and Lightglue, an attention-based matcher that lines up two images with confidence scores, and Lightglue is clever about it. On an easy image pair, it bails out after three layers in about 17 milliseconds. On a hard one, it thinks longer, going eight layers deep. It spends effort only where the scene is actually difficult. The old face and pedestrian detectors, hard cascades and hog, got moved to contrib, because deep learning detectors are now both faster and more accurate. And the old flan search got a modern replacement in an annoy. Then there is a whole layer of changes that will never trend, but quietly make everything better. Start with something as basic as number types. OpenCV finally has first class FP16 and BF16, the half precision floats that are the native currency of modern AI, living directly inside a CV submo. It also added real booleans and 64-bit integers. The manual conversion dance is over. It also learned to think intensers. There is proper support for one dimensional and even scalar arrays now with broadcasting. Sounds dull. Until you remember every model you glue open CV2 speaks exactly that language. My favorite quiet feature is the new hard wear acceleration layer. You write the same open CV code you always have, and underneath it automatically dispatches to the fastest kernel for your specific chip. Until IPP on x86, arms Clyde DCV on your phone, Qualcomm Fast CV on Snapdragon's DSP, RISK5 vector extensions on the new boards. You write it once and it quietly runs faster on every platform. The RAW performance jumped to up to two times faster on math heavy work and three to four times faster on arm for things like resizing. The whole low level intrinsic layer was rebuilt to version two. Even the boring image operations got love. Warping and remapping are anywhere from 10% to over 300% faster and contour finding got a brand new algorithm, cheekily named Truco that leaves the old fine contours in the dust and drawing text on an image finally grew up. There is a real true type renderer with an embedded font now, so you can put proper unicode labels on a frame, though complex scripts like Arabic and color emoji still are not there yet. If you work in 3D or robotics, the calibration story alone might sell the upgrade. Multi camera calibration now happens in a single call, point cloud and mesh files load natively, and depth fusion is built right in. Robust estimation got smarter too. The USA framework with modern methods like MagSack is now the default for things like homography, so your reconstructions hold up better on noisy real world data. And all those small efficient vision models open CV ships, they now live on hugging face and on an x format, so you can pull them from anywhere or use them in other frameworks entirely. They cleaned up the outside too. Roughly half the old C++ samples were deleted or rewritten and the documentation moved to a modern site, persistent navigation, instant search, dark mode, small thing, big daily quality of life win, zoom out and the scale is wild. This is a library with around a million installs every single day and nearly 90,000 github stars. A change this big ripples across a huge chunk of the software world, so should you upgrade? If you use the dnn module, yes, but test it first. The auto engine makes the switch painless and the reward is running models you flat out cannot run before. And honestly, the whole story is a little poetic. Open CV helped kick off the computer vision era, then drifted while deep learning sprinted ahead. Version 5 is it lacing up and chasing the pack down and mostly catching them. One folder, one library that now does classical vision, deep learning and language models on your CPU.
