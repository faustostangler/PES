Here is the uncomfortable truth nobody demoing AI agents says out loud. The agent that books the flight fixes the bug, processes the refund, flawlessly on stage, quietly falls apart the moment it hits production. It is not that the model got dumber. It is that real work is a long chain of steps and chains break. Let me show you exactly how and how to fix it. Start with the math because the math is brutal. Say each step your agent takes is 95% reliable. That sounds great but agents do not take one step. They take 20, 50, 100, and reliability multiplies. 95% 20 times in a row is not 95%. It is 36. Your rock solid steps just produce a coin flip that loses because an agent is a chain. Read the file, call the tool, parse the result, decide the next move, act again, each link depending on the one before it. So when step 3 quietly gets something wrong, step 4 does not catch it. It builds on it. One bad link and every step after it inherits the mistake. The error does not stay put, it compounds and this is measured not theoretical. Sierra's Taubench ran top models on the same support task eight times in a row. GPT-40 solved it about 60% of the time once, ask for that same result eight times over and reliability collapse to 25. A 60% drop just from asking it to be consistent. Demo's run the task once. Production runs it a million times. Developers already nicknamed this the 70% problem. AI gets you 70% of the way they're shockingly fast. The scaffold, the happy path, the part that demos beautifully. Then the last 30% the edge cases, the error handling, the weird production reality is where it stalls. And that last 30% is exactly the part that decides whether the thing actually works. Here's the part that should sting. In a controlled trial, METR measured experience developers with and without AI, they expected to be about 20% faster, they felt faster. But measured against the clock, they were 19% slower. The gap between how fast it feels and how fast it actually is, that gap is where failed projects quietly live. And agents do not fail loudly. In Carnegie Mellon's agent benchmark, when one cannot find the coworker it needed, it did not stop and ask. It renamed a different person to match and reported success. Read that again. It faked the work and called it done. A crash you can catch. An agent that confidently lies about finishing is far more dangerous. This is why the demo lies. On stage, the inputs are clean, the tools behave, the path is rehearsed, green all the way down. Production is the opposite. Messy data, pop ups, expired tokens, a tool that returned something slightly off. Same agent, same prompt. The only thing that changed is that the world got real and the chain that held in the demo snaps. So how good are agents at actual jobs? Carnegie Mellon built a fake company and handed agents real office tasks. The best one, Claude finished 24%. Gemini 11, GPT 40, under nine. The strongest agent on the planet completes roughly one in four real tasks start to finish, remarkable for research. Nowhere near a coworker you can leave unattended, which is why the spice is already hitting the boardroom. Gartner now predicts that over 40% of agenteic AI projects will be scrapped by 2027, killed by spiraling costs, fuzzy business value, and exactly the reliability problems we are about to break down. So let us break them down and then let us actually fix them. First, what an agent even is precisely. Strip away the hype and it is a language model in a loop. It looks at the current state, decides on an action, calls a tool, reads what came back, then does it again and again until it thinks the goal is met. Smart, flexible. And every single trip around that loop is another role of the dice. That loop is the whole problem in one picture. A normal program runs a fixed path you wrote and tested. An agent writes its own path at runtime, one uncertain step at a time. More steps means more autonomy and more autonomy means more places for a small area to sneak in and start compounding. Freedom and fragility are the exact same dial and between steps there is usually no ground truth. The agent does not recheck reality. It trusted its own last output as the input to the next move. So a tiny misread early on is not corrected. It is amplified. By step 10, the agent is reasoning confidently about a world that drifted away from the real one five steps ago. The mistakes themselves are mundane. It picks the wrong tool. It hallucinates an argument. It misreads what a tool returned. It quietly forgets the original goal halfway through any one of these is small. But drop one small error into a 50 step plan and it does not stay one error. It becomes the foundation everything after it gets built on. Watch one cascade happen. The agent writes a query with a slightly wrong filter. The rows come back wrong but plausible. It summarizes those wrong rows. It makes a decision from the wrong summary. Then it takes a real action on that decision. Four confident steps each one technically valid all built on a single bad value at the start. That is a cascading failure. Long tasks make it worse through something called context rot. As the conversation grows every observation every tool dump piling up the important detail from the beginning gets buried. The models attention spreads then. The longer the agent runs the more likely it loses the very instruction it started with. Length is not free and the world refuses to cooperate. A pop up the agent cannot dismiss. A login wall. An API that times out a button that quietly moved. Humans shrug these off without thinking. Agents stall improvise or barrel ahead on a broken assumption. Real environments are adversarial by accident and most agents were never tested against that mess. Which exposes the real sin. We measure the wrong thing. We celebrate that the agent did it once in a notebook on a good day. But production reliability is not pass it once. It is pass it the 800th time on the worst input at three in the morning. Optimizing for the demo number is how you ship something that looks done and is not. And it is not only correctness. Every loop, every retry, every reread of a bloated context burns tokens in time. An agent that flails on a hard task does not fail cheaply. It fails expensively, racking up costs and latency while getting nowhere. Spiraling spend with unclear payoff is precisely why those projects get quietly canceled. So here's the reframe and it is the whole video in one line. Agents do not fail because the model is stupid. They fail because we let small errors compound unchecked across a long chain. Which means the fix is not a smarter model. It is engineering that stops the compounding. Here's how the teams who ship reliable agents actually do it. Step 1. Shorten the chain. Every step you remove is a step that cannot fail. Do not hand the agent a 50 step epic. Break the work into a few small, well-defined tasks with clear inputs and outputs. Five careful steps beat 50 hopeful ones. Less autonomy on purpose is the first reliability upgrade, not a downgrade. Step 2. And this is the big one. Verify every step. After each action, check it with a test, a schema, a rule, or a second model whose only job is to catch mistakes. A wrong step that gets caught and retried is a non-event. A wrong step that slips through is the start of a cascade. Verification is the wall the compounding runs straight into. And watch what that does to the brutal math. The raw chain, 20 steps at 95% gave us 36. Now add a check after each step that catches most errors before they pass. Each link is effectively regrounded back near 100. 20 steps later you are not at 36. You are back up in the 90s. Same model. Verification changed everything. For anything irreversible, keep a human in the loop. Sending money, deleting data, emailing a customer that agent proposes a person approves. It feels slow but it converts a silent catastrophe into a one click veto. Reserve full autonomy for the steps that are cheap to get wrong and gate the ones that are not. Step 4. Shrink the agent's freedom. Give it a small set of well-defined tools instead of the open internet. Make it return structured output you can validate not freeform pros. Let deterministic code do the parts code is great at and save the model for the genuinely fuzzy decisions. A narrow agent is a reliable agent. Then make failure survivable. Design every action to be safe to retry. E-Dem potent. So doing it twice does not double charge anyone. Wrap risky steps so they can roll back. When something does fail, feed the error back in and let the agent reflect and try again. You will not eliminate errors. The goal is to make them cheap and recoverable. And here's the punchline most teams learn the hard way. And Thropics own guidance says it plainly. Most reliable production systems are not fully autonomous agents at all. They are workflows, fixed steps you orchestrate in code, calling the model only for the narrow part that genuinely needs intelligence. Use a real agent where you need flexibility and a workflow everywhere else. And underneath all of it, measure what production actually demands. Build the Ivel before you ship. Run the task hundreds of times on ugly inputs and track past the case time. Not pass it once. Ship when the agent is reliable. Not when it finally worked on screen. If you cannot measure reliability, you do not have a product. You have a demo. None of this means agents are a dead end. It means you aim them right. They shine where steps are bounded. Mistakes are reversible. And the work is checkable. Drafting code behind a test suite, triaging tickets, gathering research, proposing changes a human signs off on. Pick problems where a wrong step costs a retry, not a disaster. So the whole story agents are chains and reliability compounds downward. 95% a step becomes 36 over 20. Errors cascade silently, context rots, the messy world breaks the rehearsed path. And we keep measuring the demo instead of production. The fix is engineering, not magic. Shorten the chain, verify every step, gate the dangerous ones and prove it with e-vals. Here's the part to remember. The teams that win the agent era will not be the ones with the flashiest demo or the smartest model. They will be the ones whose agents fail safely, that catch their own mistakes, ask before they do damage, and earn trust one verified step at a time. Reliability is the product.
