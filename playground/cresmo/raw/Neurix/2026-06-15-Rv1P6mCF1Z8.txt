Mas antes de vermos como Kim faz isso, você pode se perguntar: o que exatamente é um ataque XXS?

XXS significa cross-site scripting (script entre sites). O nome é historicamente confuso. Na realidade, significa injeção de código em uma página da web. O objetivo é enganar um site para que ele envie código malicioso para os navegadores de outros usuários. Eis a ideia básica.

Os sites modernos são interativos. Eles recebem informações dos usuários, como avaliações, comentários, biografias de perfil e consultas de pesquisa, armazenam-nas em um banco de dados e, em seguida, as exibem na página. Normalmente, isso não é um problema. O usuário digita: "Ótimo produto". O site armazena essa informação e a exibe para outros visitantes.

Mas e se o usuário não digitar "Ótimo produto"? E se eles digitarem código HTML ou JavaScript ? Se o site não higienizar cuidadosamente os dados inseridos antes de exibi-los, o navegador não conseguirá diferenciar entre o conteúdo pretendido pelo site e o conteúdo injetado pelo atacante. Ele simplesmente executa tudo o que lhe é dado. Esse é o tamanho XXS.

Em outras palavras, o navegador do visitante interpreta a entrada do atacante como parte da própria página e a executa. Você pode traçar um paralelo com a injeção de SQL. Tanto a injeção de SQL quanto o XXS são ataques de injeção em que o atacante fornece uma entrada que é tratada como código. A diferença? A injeção de SQL tem como alvo o banco de dados do servidor, enquanto o XXS tem como alvo o navegador do usuário, o cliente. É

por isso que o XXS é frequentemente considerado um ataque do lado do cliente, enquanto a injeção de SQL é principalmente um ataque do lado do servidor. Escapar cada entrada do usuário antes de exibi-la.

[música] Esta é a solução fundamental. Sempre que um site exibir conteúdo proveniente de um usuário, caracteres perigosos como menor que, maior que, aspas duplas e aspas simples devem ser convertidos em entidades HTML inofensivas. Então o navegador os exibe como texto em vez de executá-los. Em PHP, isso é uma única função, chamada htmlspecialchars. Outras linguagens possuem funções equivalentes.

Frameworks modernos como React ou Angular escapam vulnerabilidades por padrão, tornando o XSS mais difícil de escrever do que de evitar. Valide a entrada na entrada e ignore-a na saída. São dois trabalhos diferentes. A validação rejeita entradas que não fazem sentido. Um campo de avaliação não deve aceitar tags HTML. O

mecanismo de escape processa qualquer entrada que tenha sido transmitida, tratando-a como dados quando for exibida. A validação por si só não basta. Os atacantes são habilidosos em contornar os filtros e a fuga por si só deixa apenas casos extremos. Aplique ambas as camadas. Por fim, defina o sinalizador "somente HTTP" para cookies de sessão.
