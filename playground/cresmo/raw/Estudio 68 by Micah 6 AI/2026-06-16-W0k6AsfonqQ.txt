  PERGUNTAS FREQUENTES
  P: O que é um AI Gateway?
  R: É uma camada intermediária entre sua aplicação e os modelos de IA que você usa. Funciona como guarda de trânsito: decide qual modelo usar para cada tarefa, faz fallback automático se um modelo ficar indisponível, registra custos por funcionalidade, e centraliza as chaves de API com segurança.  
  
  P: Como o AI Gateway teria protegido do ban do Fable 5? 
  R: Com fallback configurado, quando o gateway tentasse o Fable 5 e recebesse erro de indisponibilidade, automaticamente desviaria para outro modelo na lista (Claude Sonnet, GPT-4o, Gemini Flash) sem que a aplicação parasse. O usuário não perceberia a troca.
  
  P: O que é roteamento semântico em AI Gateway?
  R: É quando um modelo de IA minúsculo classifica a intenção do pedido do usuário e direciona para o modelo mais adequado automaticamente. Tarefas simples vão para modelos baratos. Tarefas complexas vão para modelos mais poderosos. Tudo transparente para o usuário final.
  
  P: Por que não chamar a API de IA diretamente do frontend?
  R: A chave de API fica exposta no código que roda no navegador de qualquer usuário. Qualquer pessoa que inspeciona o código pode roubar a chave e usar em nome da sua conta. A arquitetura correta é: Frontend → Backend (seu) → AI Gateway → APIs dos modelos.
  
  P: O que é Concentração de Dependência em IA?
  R: É quando uma organização depende de um único modelo ou vendor de IA para processos críticos, sem alternativa designada e sem plano de contingência. O ban do Fable 5 foi o primeiro caso global de exposição em escala desse risco.
  
  P: Quais são as ferramentas de AI Gateway mais usadas?
  R: LiteLLM (código aberto, gratuito, mais popular), Portkey e Helicone (plataformas SaaS com dashboard de custos e observabilidade), e Cloudflare AI Gateway (com caching nativo que elimina custo em perguntas repetidas).
